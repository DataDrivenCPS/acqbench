Verdict. The updated ums-timescale-fix (4267175: psycopg path kept, hypertable re-keyed by integer ref_id, one unique index) reaches the same footprint as fix-2 (12.8 GB, 94 B/row, 7.2 GB table + 5.6 GB index — identical schema on disk) and gets 1.77× ingest against its same-day main (29.9 → 16.9 min, 76k → 135k rows/s), while no read regresses: median query p50 0.92× main, every one of the 30 queries between 0.77× and 1.17×, with the ≥ 60k-row scans 8–10% faster and cold first-touch reads ~25% faster on the big streams. The latest N / LIMIT shapes stay at ~2 ms, exactly where main has them.

The ingest gain from old to new fix-1 (1.44× → 1.77×) is what the narrower rows and the 5× smaller unique index buy on the unchanged psycopg upsert path; Postgres is still the single ~0.9-core bottleneck with acquirium idle at 0.14 cores. fix-2's further step to 2.30× comes from moving the staging work into the acquirium process (0.75 cores) and replacing ON CONFLICT with delete-then-insert — but that is also what costs it the LIMIT pushdown and adds a ~4 ms floor to point reads.
Recommendation. The new fix-1 is the safe merge: it captures all of the disk win and most of the ingest win with zero read-side risk. fix-2 is only worth its read-path regressions if large-scan latency matters more than latest-value reads — and if its LIMIT handling is fixed (push ORDER BY ts … LIMIT n into the Postgres SQL via postgres_query()) it would dominate on everything except the ≤ 400-row point reads, where the ~4 ms DuckDB-attach floor remains.
Comparability. Each variant ran immediately after a fresh run of the same main commit on the same day (09-02 for old fix-1, 09-04 for fix-2 and, in a later campaign, new fix-1). main's ingest and disk reproduced exactly on all three days (30.4/30.4/29.9 min, 66.47 GB), but its large-scan latencies varied 384–484 ms with host load, so raw milliseconds are not comparable across columns — the "÷ main" ratios are. The duckdb column is main's duckdb backend from 09-04 (unchanged by any of these branches), for scale.
